# 订单与付款记录

登录 `/admin` 后，可分别查看订单记录、付款记录及单笔订单详情。记录来自指定私有 GitHub 数据仓库，浏览不依赖收款开关；关闭真实收款后仍可查看历史数据。当前源码的上线状态需要另外核对[发布状态](release-status.md)。

## 记录与筛选

订单记录包含创建中、待付款、付款成功、已关闭和支付异常订单；付款记录仅显示微信验签且核对成功的 `SUCCESS` 订单。付款成功与业务通知完成分别展示：已付款但通知待重试，不代表权益已经开通。

可按产品、订单状态、通知状态及日期筛选，也可搜索支付订单号、业务订单号、微信流水号、产品和商品信息。订单日期按创建时间筛选，付款日期按付款时间筛选。金额按订单总额展示，单位为人民币分；它不是结算入账金额，也不替代微信交易账单或资金账单。

详情展示商品、数量、金额、支付通道、创建/截止/付款/关闭时间、真实微信流水、通知状态与重试情况，以及订单事件和管理员操作历史。旧订单兼容读取，但新增功能上线前没有保存的历史事件不能补造。

列表按支付订单 ID 排序并逐页扫描，每次最多读取 20 笔订单。因此筛选结果可能为空但仍有下一页，需要继续加载；当前页不能视为全量订单、当日收入或财务汇总。订单和付款详情不向浏览器返回预支付凭据、OpenID、用户 IP、请求摘要或商户秘密。

## 超时关闭

所有通道的订单从创建起最多可支付 5 分钟。时长固定在服务端，旧 `ORDER_TTL_MINUTES` 环境变量不会延长订单有效期。业务订单号是幂等键，关闭后重试相同业务订单号仍返回原订单；需要重新购买时，由业务端生成新的业务订单号。

同一请求重试保留原订单的价格、商品描述、AppID 和截止时间，后续商品改价、下架或配置调整不会覆盖这些记录。修改数量、通道、付款人或返回地址仍会产生幂等冲突；传入 `expectedTotal` 时按原单金额核对。

下单时将截止时间提交给微信 `time_expire`。到期后收银台停止提供付款参数；访问订单时触发补偿查单，每分钟计划任务补充处理未访问订单。微信支付截止时间与订单关闭是两个阶段：超时后先查单，未付款时调用微信关单，再查询确认后记为已关闭。网络错误或存储故障时保留待处理记录，展示关闭处理中，后续继续恢复。微信的新单付款截止、后台任务开始时间和最终关单确认时间应分别核验。[微信 Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[微信关闭订单](https://pay.wechatpay.cn/doc/v3/merchant/4012791881)

统一的 5 分钟期限与微信 H5 支付跳转链接的有效期一致；本项目不会在过期后刷新链接来延长原订单。[微信 H5 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791834)

若付款与关单同时发生，以微信验签通过、金额和身份匹配的真实结果为准。不能将一次 `NOTPAY` 查单当作永久失败，也不能因为本地显示过期就忽略已经完成的付款。每分钟补偿任务有每批 10 条的处理上限，积压、GitHub 限流或平台调度仍可能延迟关闭确认。旧版已向微信提交超过 5 分钟有效期的订单，需要通过补偿关单缩短剩余付款窗口。

## 管理员操作

每次操作必须填写 3–200 字原因，操作历史记录管理员、时间、原因和结果。管理员可执行：

- **刷新微信状态**：主动查单并核对真实状态，补偿遗漏的付款或关单确认；发现已付且通知待处理时尝试投递。
- **关闭未付款订单**：先保存关闭请求，再向微信查单、关单；已付款订单拒绝关单。若另一个查单任务仍持有租约，操作可先返回关闭处理中，由后续任务完成。
- **重试业务通知**：仅适用于已付款订单。沿用稳定事件 ID，尊重正在执行的投递租约；已经送达时不重复发送。业务端仍必须按事件 ID 去重。通知连续失败达到上限后进入人工处理，可修复接收端后重试。

操作请求成功表示本次操作已处理，订单是否已关闭、通知是否已送达，应继续以详情中的状态为准。系统不提供手工改成付款成功、改金额、删除订单、重新打开关闭订单或退款功能。关单和刷新微信状态需要 `PAYMENT_MODE=live` 及有效微信配置；即使将 `PAYMENT_ENABLED=false` 暂停新下单，仍可维护既有订单。重试业务通知不依赖收款开关，但仍需原产品的有效回调配置。

暂停新下单时保留 `PAYMENT_MODE=live`、商户密钥和存储配置。既有收银台、已签名的产品查单、微信付款通知以及每分钟补偿任务继续工作，避免暂停期间遗漏到账或无法关闭超时订单。暂停不会立即撤销已经发出的有效支付参数，需要取消既有未付款订单时执行关单。`PAYMENT_MODE=demo` 会停用上述微信支付维护链路，后台管理仍可使用，业务通知可独立重试。

## 管理接口

所有接口均要求管理员会话，写入还要求同源 `Origin` 和 `X-Brclio-CSRF`。只读列表支持 `clientId`、`status`、`deliveryStatus`、`query`、`from`、`to`、`cursor`、`limit`；日期支持 `YYYY-MM-DD` 或 ISO 时间。API 直接传日期时使用北京时间（UTC+08:00）日期边界，结束日期包含当天；其他时区可传带时区的起止 ISO 时间。`limit` 为 1–20，默认 20；游标经过签名并绑定筛选条件，改变筛选后需从第一页开始。

| 请求 | 用途 |
| --- | --- |
| `GET /api/admin/orders` | 订单列表，返回 `orders`、`nextCursor`、`scanned`、`hasMore`、`sort`、`scanLimit` |
| `GET /api/admin/payments` | 付款列表，列表字段为 `payments`，其余分页字段相同 |
| `GET /api/admin/orders/:id` | 安全订单详情，返回 `{order}` |
| `POST /api/admin/orders/:id/refresh` | 查单及补偿 |
| `POST /api/admin/orders/:id/close` | 请求关闭未付款订单 |
| `POST /api/admin/orders/:id/retry-notification` | 重试已付款订单的业务通知 |

写入正文为 `application/json`，只接受 `{"reason":"人工操作原因"}`。订单历史与付款流水随订单一起加密保留；恢复索引另外保存加密订单草稿或已经验签核对的必要交易快照，以补偿存储写入中断。工作索引完成后可以清理，历史订单不会因支付链接过期而删除。Git 提交历史仍保留先前密文，保留与备份边界见[架构文档](architecture.md)。
