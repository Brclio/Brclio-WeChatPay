# 登录复制 Skill，让 AI 接入当前产品

登录 [管理后台](https://paywc.bornforthis.cn/admin)，复制通用接入 Skill，粘贴到目标产品已授权的私有 AI 开发会话。无需先手填产品名称、商品或回调：AI 会检查产品仓库中的真实配置，通过限时接入 API 登记支付中心，并修改该产品的支付与开通代码。

目标 AI 必须已经能访问你授权的工作区、源码仓库及所需部署环境。Skill 只授予支付中心内一个产品的管理能力，不会授予 GitHub、Cloudflare 或其他部署平台权限；源码修改、推送、部署和真实付款仍按该会话已有授权执行。缺少必要商品价格、生产域名或外部权限时，AI 应明确索取实际缺项，不能编造价格或假装部署完成。

## AI 应完成的工作

1. 阅读目标仓库的 `AGENTS.md` 和框架配置，检查登录态、商品价格、待购订单、原支付渠道、用户权益及部署方式。
2. 使用接入包里的 `clientId` 和限时 Bearer token，读取 `GET /api/integration/clients/:id`。未登记时的 404 代表可以登记该预留产品；不能改用其他产品 ID。
3. 从已确认的产品配置取得名称、固定 HTTPS 回调、返回域名、SKU、数量及人民币分价格，用 `PUT` 同一路径登记。现阶段只选已开通的 `native`，不自行启用 H5/APP。
4. 取得本产品独立 API/Webhook 凭据，写入产品服务端的 Secret 或已忽略环境文件，再获取 `/api/integration/clients/:id/skill` 中的最新专属说明。
5. 复用原产品订单与权益模型，加入 Brclio 微信支付。已有支付宝等渠道默认保留，必要的当前项目适配可按既有授权完成；不得为同一次购买同时创建两笔收款。
6. 接好签名下单、收银台链接、查询、原始通知验签、事务去重和对应用户的真实权益发放。浏览器或 SDK 回调不能直接开通。
7. 验证签名错误、金额不符、跨产品查询、重复通知及恢复流程；按既有授权部署产品，并报告证据及真实付款验收仍缺少的步骤。

没有可信后端的纯静态网页、APK 或桌面客户端，需要在当前产品授权范围内补充最小后端；不能把 API/Webhook 密钥打包到客户端。签名与 Webhook 事务实现参考 [完整接入文档](integration.md)、[Node SDK](../examples/brclio-pay.mjs) 和 [HTTP 接收示例](../examples/webhook-server.mjs)。HTTP 示例仍须接入真实持久化事务适配器，不能用内存 Set 冒充已开通。

## 授权范围与保管

通用 Skill 预留一个随机产品 ID，携带 24 小时有效的单产品 Bearer 授权。已有产品的专属 Skill 也附带该产品限时授权，并包含实际商品目录及长期产品服务端密钥。接入 token 只能读写所绑定产品，不能管理其他产品、修改全局商户配置、改产品 ID、轮换凭据或退款。轮换该产品凭据后，旧授权失效；到期后重新登录后台复制。

整份包都属于秘密，只能交给该产品受信任的私有开发会话。禁止提交源码、发布公开 Skill、粘贴公共工单、截图或打印日志。商户私钥、微信 APIv3 密钥、GitHub Token、管理员密码以及目标产品仓库/部署凭据不在接入包内。复制包不等于授权 AI 操作任何其他站点或账户。

运行时只保留本产品的下单 API/Webhook 密钥，不需要保存限时接入 token。产品密钥独立于商户级秘密；支付中心将产品配置与密钥加密保存在指定私有 GitHub 数据仓库，管理登录与导出通过 HTTPS 提供。

## 验收状态

当前线上 Native 已完成 0.01 元预支付创建、幂等下单、未付款查询和关单验证，没有执行扣款。首次真实产品上线仍需要完成“用户实际付款 → 微信签名通知 → 支付中心确认 → 产品事务开通权益”的验收。AI 不能把复制 Skill、创建二维码、部署成功或 SDK 成功回调写成已收款/已开通证据。详见 [发布状态](release-status.md)。

接入管理 PUT 按提供的字段更新，未提供字段保留；`products` 按 SKU 新增或更新，其他 SKU 保留，删除商品需管理员操作。并发更新会在 GitHub SHA 条件写入中重新合并，管理员暂停状态在该条件写入中保留。若目标项目已经使用本中心的另一个现有产品 ID，请从该产品卡片复制专属 Skill，避免重复创建产品和替换历史订单配置。
